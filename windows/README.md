# Заметки по Windows Server 2016

Практические наблюдения, которые пригодились при настройке контроллера домена в этой лаборатории. Могут сэкономить время тем, кто повторяет стенд.

## Локализация

Русская версия Windows Server 2016 меняет имена встроенных объектов и команд. Это ломает часть инструкций и фильтров, написанных под английский интерфейс.

- Встроенная учётная запись администратора называется **`Администратор`**, а не `Administrator`. Соответственно:
  - `SamAccountName = Администратор`
  - вход: `LAB\Администратор`
  - `Get-ADUser -Identity "Administrator"` вернёт ошибку «объект не найден»
- `whoami` покажет `lab\администратор`
- `whoami /user` покажет SID, оканчивающийся на `-500` (встроенный администратор)
- Фильтр `MemberOf -like "*Domain Admins*"` ничего не найдёт, потому что группа называется «Администраторы домена». Надёжнее искать по SID:

## Get-ADGroup -Filter {SID -like "*-512"} | Get-ADGroupMember

```
(SID `-512` - это Domain Admins, `-500` - встроенный Administrator, независимо от языка.)
- У встроенного `Администратор` по умолчанию **не задан UPN**. Чтобы использовать `Администратор@lab.local` в bind, UPN нужно задать явно:

```

## Set-ADUser -Identity "Администратор" -UserPrincipalName "Administrator@lab.local"

```
После этого в Linux-клиенте можно использовать `Administrator@lab.local` (латиницей), не мучаясь с кириллицей в bash.

## LDAP signing

Параметр `LDAPServerIntegrity` определяет, требуется ли подпись LDAP:

- `0` - не требуется
- `1` - требуется (по умолчанию в Windows Server 2016)
- `2` - не требуется, но клиент может согласовать

Путь в реестре:

```

## HKLM\SYSTEM\CurrentControlSet\Services\NTDS\Parameters\LDAPServerIntegrity

```
При значении `1` простые bind по порту 389 без TLS отклоняются с ошибкой `52e` (`Invalid credentials`), даже если пароль верный. Это часто сбивает с толку при первой настройке LDAP.

Правильное решение - не отключать подпись, а перейти на LDAPS (порт 636). TLS удовлетворяет требованию целостности, и `LDAPServerIntegrity = 1` можно оставить.

Проверка:

```

## Get-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\NTDS\Parameters' -Name 'LDAPServerIntegrity'

```
## AD CS: чего нет в интернете

- Командлет `Publish-CATemplate` **не существует**, хотя встречается в статьях. Используйте:

```

## Add-CATemplate -Name "LDAPS-Template" -Force

```
или `certutil -SetCaTemplates`.
- `Install-AdcsCertificationAuthority` при успехе возвращает `ErrorId : 0` без текстового сообщения. Это не ошибка, а штатное завершение.
- `Get-Certificate` создаёт **новый** сертификат при каждом вызове. Старый остаётся в хранилище, пока его не удалить вручную. Для демонстрации «ротации» это может быть полезно, но для чистоты лучше удалять старые.
- Пункт «Создать → Выдаваемый шаблон сертификата» в русской оснастке `certsrv.msc` иногда не появляется. Обходной путь - публикация через `Add-CATemplate` из PowerShell.

## Evaluation-версия

- Срок: 180 дней с момента установки.
- По истечении сервер перестаёт загружаться, но данные не теряются.
- Для лаборатории это допустимо: стенд можно пересоздать с нуля за вечер.
- Для продленияEvaluation есть команды `slmgr`, но в изолированной лаборатории это не критично.

## Полезные оснастки

- `dsa.msc` - Active Directory Users and Computers (пользователи, группы, OU)
- `dnsmgmt.msc` - DNS (зоны `lab.local`)
- `certsrv.msc` - центр сертификации (AD CS)
- `certlm.msc` - сертификаты локального компьютера (нужно для выдачи сертификата DC01)
- `certtmpl.msc` - шаблоны сертификатов (дублирование и настройка)
- `ldp.exe` - лёгкий LDAP-клиент для локальной проверки bind (удобно для отладки, отделяет проблему AD от проблемы клиента)

## RDP и VMConnect

На Windows Server 2016 RDP (удалённый рабочий стол) по умолчанию выключен. Включается через:
- «Диспетчер серверов» → «Локальный сервер» → «Удаленный рабочий стол»
- или PowerShell:

```

## Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' -Name 'fDenyTSConnections' -Value 0
## Enable-NetFirewallRule -DisplayGroup "Remote Desktop"

```
- В лаборатории RDP не обязателен: VMConnect с `/edit` (расширенный сеанс) даёт буфер обмена и проброс дисков, этого достаточно.
- При входе под `LAB\Администратор` расширенный сеанс может откатываться в базовый - в этом случае файлы удобно копировать под локальным администратором в `C:\Temp`, а работать под доменным.
```
